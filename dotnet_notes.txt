using System; — Imports the core system namespace containing built-in classes (comparable to Python's import statement, like import sys).

namespace new_namespace — Creates a logical grouping container for your classes to prevent naming conflicts (similar to organizing code into a custom Python package or directory structure).

{ — Opens a code block for the namespace (C# uses curly braces {} to define blocks, whereas Python uses indentation).


class Program — Declares a container class named Program (in C#, every line of executable code must live inside a class, unlike Python where you can write code directly at the top level).


static void Main(string[] args) — The mandatory entry point method where program execution automatically begins (equivalent to Python's if __name__ == "__main__": setup).


Call-by-Reference (ref keyword)
What it is: By default, C# passes value types (like integers) by value (it copies the data). Using the ref keyword forces C# to pass the variable by reference, meaning changes made inside the function directly modify the original variable




Class-Level Static State Retention
What it is:

Local variables inside a regular method (AutoStorageDemo) are wiped and re-initialized to 0 every time the function runs.

A class-level static variable (staticCounter) lives in memory for the lifetime of the program, retaining its updated value across multiple different function calls.

Access modifiers are keywords in C# that control the visibility and accessibility of classes, methods, and variables. Unlike Python—which uses naming conventions like leading underscores (_protected or __private)—C# enforces security and encapsulation strictly at compile time.


Summary of Core Access Modifiers
Access ModifierAccessible Where?
public	Anywhere in your entire program (no restrictions).
private		Only inside the exact same class or struct where it is declared.
protected	Inside the class and any child (derived) classes that inherit it.
internal	Anywhere within the same project/assembly, but not outside it.

Understand why each part is there
A. Controller declaration
[Route("api/[controller]")]
[ApiController]
public class StudentsController : ControllerBase


[Route] defines the base URL.

[controller] automatically takes the controller name without the Controller suffix.

Therefore:
StudentsController → /api/students


[ApiController] enables API-specific behavior, including automatic request validation and binding.

ControllerBase provides methods such as Ok(), NotFound() and CreatedAtAction().

B. Dependency Injection
private readonly AppDbContext _context;

public StudentsController(AppDbContext context)
{
    _context = context;
}


We receive the database context through the constructor instead of creating a database connection manually.

This is called constructor injection.

C. Create operation
_context.Students.Add(student);

await _context.SaveChangesAsync();


Add() marks the student as a new entity.

SaveChangesAsync() actually executes the INSERT operation against MySQL.

D. Read operation
var students = await _context.Students.ToListAsync();


Returns all student records.
var student = await _context.Students.FindAsync(id);


Finds one student using its primary key.

E. Update operation
student.Name = updatedStudent.Name;
student.Email = updatedStudent.Email;
student.Age = updatedStudent.Age;

await _context.SaveChangesAsync();


We retrieve the existing database record, modify its properties and save changes.

EF Core tracks the retrieved entity, so it knows which record needs updating.

F. Delete operation
_context.Students.Remove(student);

await _context.SaveChangesAsync();


Remove() marks the record for deletion.

SaveChangesAsync() executes the DELETE operation.
Why do we use async and await?
Database queries involve waiting for another system (MySQL).

Using asynchronous methods prevents the server thread from being blocked while waiting for database responses.

This is particularly useful when multiple API requests arrive simultaneously.
Why do we return IActionResult?
Because an API should return appropriate HTTP status codes rather than simply returning data.
Method	Meaning
Ok()	200 – Successful
CreatedAtAction()	201 – Resource created
NotFound()	404 – Record not found
BadRequest()	400 – Invalid request
